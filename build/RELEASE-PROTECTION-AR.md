# إصدار Windows الموقّع

التحقق الداخلي يحتاج المفتاح العام المدمج وبيان الملفات وتوقيعه. مفتاح الإصدار الخاص غير موجود في حزمة المصدر. هذا مقصود حتى لا يستطيع من يحصل على حزمة التوزيع توقيع ملفات معدلة بالمفتاح نفسه.

لتطوير نسختك المملوكة لك، خزّن مفتاحًا خاصًا خارج مستودع المصدر. يمكنك تهيئة مفتاح جديد أو استخدام المفتاح الذي احتفظت به:

```powershell
pwsh build/Initialize-ReleaseKey.ps1 -PrivateKeyPath C:\Private-Lumora\release.private.pem
```

بعدها ابنِ هدف Windows في Release وانشره مع ملفاته الأصلية في مجلد مستقل. ثم وقّع المجلد:

```powershell
pwsh build/Sign-Windows-Release.ps1 -Directory C:\Lumora-Publish -PrivateKeyPath C:\Private-Lumora\release.private.pem
```

لا تنشر المفتاح الخاص أو تنسخه إلى APK أو المثبّت أو حزمة المصدر. الملف العام `Assets/release-public.pem` آمن للنشر ومقصود أن يكون داخل التطبيق. إذا غيرت المفتاح العام يجب إعادة بناء الملف التنفيذي قبل توقيع المجلد. إذا غيرت رقم الإصدار فحدّث كذلك الرقم المتوقع في `DesktopRelease.cs`.

تحقق قبل التوزيع:

```powershell
C:\Lumora-Publish\Lumora.exe --release-check C:\Lumora-Publish\check.json
```

رقم الخروج صفر وتقرير `passed: true` يعنيان تطابق الملفات مع البيان. احزم الملفات المنشورة نفسها والتوقيع في المثبّت. تحديث ملف تنفيذي بعد توقيع البيان يتطلب إعادة التوقيع؛ تغيير ملف بعد بناء المثبّت يتطلب إعادة بناء المثبّت.

حماية Android تتحقق من بصمة الشهادة المعتمدة في `AndroidReleaseIdentity.cs`. احتفظ بمفتاح APK الأصلي لتستطيع تحديث التطبيق الموجود. إذا كنت تملك نسخة جديدة وتوقعها بمفتاح مختلف، حدّث البصمة في المصدر قبل بنائها؛ لن تستطيع تثبيتها فوق تطبيق موقّع بمفتاح آخر.

هذه طبقات تحقق محلية، وليست تنشيطًا عبر خادم أو نظام دفع، وليست ضمانًا لاستحالة تجاوز الفحوص. حماية iOS تعتمد على توقيع Apple وملف provisioning. تبقى تراخيص مكتبات الطرف الثالث نافذة.
